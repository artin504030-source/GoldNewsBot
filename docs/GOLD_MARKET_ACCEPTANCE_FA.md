# مرحله I — تست یکپارچگی و پذیرش Gold Market

## هدف
اثبات آفلاین و قابل‌تکرارِ مسیر کامل داده تا پیام:
1. جمع‌آوری هفت نماد بازار از providerهای مجزا
2. اعتبارسنجی timestamp، محدوده قیمت و freshness
3. تحلیل روند و نوسان با تاریخچه کندل‌های تکمیل‌شده
4. مقایسه با snapshot قبلی و افزودن ریسک رویداد
5. ساخت گزارش فارسی
6. تبدیل گزارش به HTML امن و تقسیم پیام تلگرام

## فایل آزمون
`tests/test_gold_market_acceptance.py`

سه سناریوی پذیرش پوشش داده شده‌اند:
- مسیر موفق کامل: هر هفت نماد، برچسب‌های LIVE/DELAYED/DAILY، روند، زمینه بین‌بازاری، رویداد، گزارش فارسی و escaping HTML.
- خرابی جزئی providerها: نبود قیمت طلا و خطای تاریخچه باعث توقف کل pipeline نمی‌شود؛ تحلیل UNAVAILABLE و هشدارهای صریح نمایش داده می‌شوند.
- استفاده مجدد از یک snapshot: قالب‌سازی چندباره باعث جمع‌آوری مجدد داده نمی‌شود.

## اجرای محلی/CI
```bash
python -m unittest discover -s tests -p "test_gold_market_*.py" -v
```

تمام providerها در آزمون‌های پذیرش stub شده‌اند؛ هیچ درخواست HTTP واقعی، توکن تلگرام، ارسال پیام یا زمان‌بندی اجرا نمی‌شود. workflow موجود Gold Market Tests همین الگوی نام‌گذاری را اجرا می‌کند و آزمون پذیرش جدید را نیز خودکار پیدا خواهد کرد.

## معیار پذیرش
- داده‌های مفقود یا نامعتبر هرگز با عدد ساختگی جایگزین نشوند.
- وضعیت و منبع هر مشاهده حفظ شود.
- خرابی یک provider کل snapshot را متوقف نکند.
- گزارش HTML تمام متن‌های پویا را escape کند.
- پیام‌ها از سقف محافظه‌کارانه ۳۹۰۰ کاراکتر عبور نکنند.
- هیچ side effect تلگرامی در تست وجود نداشته باشد.

## محدوده خارج از این مرحله
اتصال Telegram Bot API، ارسال کانال، زمان‌بندی ۶۰ دقیقه‌ای، فعال‌سازی Secrets جدید و merge به `main` عمداً انجام نمی‌شوند و نیازمند تأیید جداگانه‌اند.
