# مرحله G — موتور گزارش بازار طلا

## هدف
تبدیل خروجی ساختاریافته موتور تحلیل مرحله F به گزارش فارسی قابل‌خواندن، بدون وابستگی به تلگرام و بدون اجرای زمان‌بندی.

## اجزای پیاده‌سازی
- `apps/gold_market/report.py`: تابع مستقل `render_market_report(assessment, observations, generated_at)`.
- `apps/gold_market/collector.py`: متد `collect_report_snapshot` یک مجموعه مشاهده، نتیجه تحلیل و وضعیت جمع‌آوری را در یک اجرای هماهنگ برمی‌گرداند. متد قبلی `assess_market` برای سازگاری حفظ شده است.
- `apps/gold_market/__main__.py`: اجرای واقعی جمع‌آوری، چاپ گزارش فارسی و سپس خروجی JSON ماشین‌خوان.

## بخش‌های گزارش
1. زمان تولید گزارش و زمان آخرین داده استفاده‌شده در تحلیل.
2. رژیم بازار، روند، نوسان، اطمینان، حمایت، مقاومت و ATR.
3. قیمت و منبع XAUUSD، DXY، US10Y، US02Y، USOIL، SPX و VIX در صورت دسترسی.
4. برچسب وضعیت منبع: زنده، با تأخیر، روزانه، قدیمی یا در دسترس نیست.
5. زمینه بین‌بازاری، سناریوی اصلی و جایگزین.
6. ریسک رویدادها و هشدارهای کیفیت داده.
7. یادآوری صریح اینکه گزارش سیگنال قطعی یا توصیه مالی نیست.

## قواعد ایمنی و صحت
- مقدار، زمان، منبع، واحد و وضعیت هر مشاهده از داده واقعی همان اجرای collector گرفته می‌شود.
- مشاهده ناموجود به‌عنوان «در دسترس نیست» یا «نامشخص» نمایش داده می‌شود؛ مقدار جایگزین ساخته نمی‌شود.
- زمان‌ها با UTC نمایش داده می‌شوند تا ابهام منطقه زمانی کاهش یابد.
- داده‌های زنده، تأخیری و روزانه از هم تفکیک می‌شوند.
- محرک‌های بین‌بازاری زمینه‌ای هستند و رابطه علّی یا پیش‌بینی قطعی ادعا نمی‌کنند.
- گزارش هیچ پیام تلگرامی ارسال نمی‌کند و scheduler را فعال نمی‌کند.

## اجرا
```bash
python -m apps.gold_market
```
در صورت موفق بودن ارزیابی روند، کد خروج صفر است؛ اگر تاریخچه طلا برای ارزیابی روند کافی نباشد، کد خروج غیرصفر خواهد بود. گزارش متنی و JSON در stdout چاپ می‌شوند.

## آزمون
```bash
python -m unittest discover -s tests -p "test_gold_market_*.py" -v
```
آزمون‌های گزارش شامل ساختار بخش‌های فارسی، نمایش قیمت و وضعیت منبع، داده ناقص و محرک ناشناخته هستند.
